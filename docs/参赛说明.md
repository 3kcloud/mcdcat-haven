## 一、作品定位（一句话）

把你在麦当劳的每一笔消费，按 **¥1 = 10g** 换算成「爱心猫粮」，用来喂养一只你领养的流浪猫；投喂满 20 次，它会走完 *相遇 → 熟悉 → 信赖 → 新家* 四阶段，戴上红领巾被领养，并生成一张可分享的领养证书。

**差异化护城河**：公益叙事 + 真实数据驱动。城市流浪猫题材在大赛现有创意中几乎空白；所有成长进度由麦当劳 MCP 真实订单数据驱动，而非虚构数值——这是作品的硬核评分点。

---

## 二、创意背景

程序员群体是麦当劳高频消费者，也是领养流浪动物的高认同人群。我们想用「最低门槛的善意」把两者连接起来：

- 不要求捐款、不要求复杂操作，把日常点单转化为对流浪猫的「虚拟喂养」；
- 用游戏化叙事轻声倡导「领养代替购买」「科学喂养 · TNR」，而非说教；
- 把品牌订单数据变成一件有温度的事，让高频消费者在熟悉的产品里遇见陌生的小生命。

## 三、核心玩法

| 环节 | 说明 |
|---|---|
| **领养** | 从 6 只麦当劳特色流浪猫中选一只（每只都有被遗弃 / 流浪的身世设定） |
| **获取猫粮** | A 麦门主食（真实订单金额换算）/ B 爱心任务（签到 + 浏览菜单·营养·活动）/ 演示模式 |
| **投喂** | 每 100g = 1 次投喂，每阶段需 5 次，共 20 次 |
| **成长** | 4 阶段立绘随之变化（瘦弱警惕 → 圆润微笑 → 红领巾新家） |
| **成就** | 喂养里程碑解锁「成就卡」，可保存分享（卡片内嵌仓库短链） |
| **结局** | 走完 4 阶段 = 找到家，出具领养证书分享图 |

**双通道设计**：A 通道靠真实订单、B 通道靠签到与浏览任务，两条线都能独立走到结局——确保不点外卖的程序员也能完整体验，不被真实消费门槛阻拦。同时，玩家的 Star 行为与任何游戏解锁完全脱钩（合规）。

**6 只猫**（麦当劳特色 × 流浪身世）：小橘🍟 / 奶昔🍦 / 芝麻🍔 / 团子🍗 / 玄米🥤 / 芋圆🥧。

**8 级爱心称号**：拾粮人 → 投喂实习生 → 麦麦饲养员 → 暖爪管理员 → 爱心站长 → 猫屋主理人 → 麦门守护者 → 流浪猫之友（隐藏）。只展示等级与称号、**不展示消费金额**——成就感保留，攀比压力去掉。

## 四、真实调用麦当劳 MCP（核心评分点）

已真机验证调用麦当劳中国官方 MCP Server（`mcd-mcp` v1.0.0，共 35 个 tools，验证日期 2026-10-11）：

| 玩法环节 | MCP Tool | 数据层 | 用途 |
|---|---|---|---|
| 订单金额 → 猫粮换算 | `order-list` | 个人（需授权） | 主线喂养 A 通道 |
| 菜单 / 爱心餐素材 | `query-meals` | 公开 | 爱心餐素材、任务系统 |
| 营养数据 | `list-nutrition-foods` | 公开 | 营养正向展示（仅蛋白质 / 均衡） |
| 一键领券（里程碑奖励） | `auto-bind-coupons` | 个人（需授权） | 成长里程碑真实奖励（已真机领券成功） |

**换算逻辑**：取 `order-list` 返回的 `realTotalAmount` 求和，按 **¥1 = 10g** 换算为猫粮；仅读取金额数值，不存储订单明细、不记录商品清单。

**分层数据设计**：菜单 / 营养等公开数据由服务端用开发者 Token 缓存共享，全员零门槛即可体验真实数据驱动的玩法；订单与领券等个人数据需玩家主动授权，Token 仅经服务端环境变量中转、不落库不留存。

> 完整调用时序、返回结构与验证记录见仓库 **[MCP_INTEGRATION.md](./MCP_INTEGRATION.md)**。

## 五、交互与体验亮点

玩家的每个操作都得到**三层叠加反馈**：触感（振动）→ 声音（WebAudio 合成，无外部资源）→ 视觉。

- **猫咪待机**：立绘持续「呼吸起伏 + 偶尔歪头」，静态图也有生命感
- **投喂**：猫粮颗粒抛物线飞向猫咪 → 抵达时挤压回弹「进食」→ 爱心粒子上浮 → 气泡台词
- **猫粮增减**：数字滚动（不瞬间跳变）+ `+150g` / `-100g` 飘字 + 数值条脉冲高亮
- **点击手感**：所有按钮统一按压缩放 + 涟漪扩散
- **无障碍**：遵循 `prefers-reduced-motion`，自动降级为「只变色不运动」

## 六、公益与合规（底线）

- 🌱 **猫粮是「虚拟喂养量」，不是「喂人类食品」**：绝不出现「喂猫吃薯条 / 汉堡」意象；页面明示 *现实中请勿随意投喂人类食品给猫咪，科学喂养请咨询兽医*。
- 🚫 **不承诺任何真实捐赠**：爱心猫粮为游戏内虚拟数值，不代表任何真实捐赠或实物兑换。
- 🐾 **猫咪角色与故事均为虚构**，旨在倡导「领养代替购买」与科学喂养、TNR 绝育等理念。
- 📊 **不展示热量 / 卡路里数字**，营养仅作正向表述，规避不健康饮食导向。
- 🔒 **隐私**：Token 仅存服务端环境变量；个人订单仅读取金额，不落库、不上送第三方。
- ⭐ **合规边界**：所有游戏奖励由游戏成就解锁，与 GitHub Star 完全脱钩。

## 七、技术栈与结构

- **前端**：Vite + TypeScript（DOM / CSS 动画 · `html2canvas` 分享图 · `localStorage` 存档）
- **后端**：Vercel Serverless（`api/mcp-order.js`）作 MCP 代理层，解决浏览器直连 `mcp.mcd.cn` 的 CORS 跨域
- **资产**：6 猫 × 4 阶段 = 24 张真透明 PNG 立绘

```
.
├── index.html
├── src/
│   ├── data.ts     # 6 猫档案 · 四阶段 · 称号 · 配置
│   ├── logic.ts    # 状态 · 猫粮换算 · 投喂成长
│   ├── ui.ts       # 首页 / 详情 / 证书渲染
│   ├── share.ts    # html2canvas 分享图
│   └── main.ts     # 路由与事件
├── api/mcp-order.js        # MCP 代理（order-list → 金额）
├── public/assets/cats/     # 24 张真透明立绘
├── MCP_INTEGRATION.md      # MCP 真实调用说明
└── mcp-config.example.json # MCP 配置示例（脱敏）
```
